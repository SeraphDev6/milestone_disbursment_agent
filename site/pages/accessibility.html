Accessibility statement

Accessibility at Milestone Ledger

Money that moves on evidence should be usable by everyone who is party to it. This statement covers this website and the web application at app.milestone-ledger.com.

Prepared November 6, 2026·Target: WCAG 2.2 Level AA

Our commitment

We want every side of an agreement, funder, grantee, contractor, client and reviewer, to be able to read the criteria, submit evidence, follow a verdict and release a payment without barriers. Accessibility is part of the design system the product is built on, not a check at the end.

Conformance status

The Web Content Accessibility Guidelines (WCAG) 2.2 define requirements for designers and developers to improve accessibility for people with disabilities. They have three levels of conformance: A, AA and AAA.

  • This website is designed to be fully conformant with WCAG 2.2 Level AA. Every page is checked automatically in all three themes before it is published.
  • The web application is designed to be conformant with WCAG 2.2 Level AA. We describe it as partially conformant because some manual checks listed under known limitations have not been completed yet.

What we have done

Reading

  • Body text is set in Atkinson Hyperlegible Next, a typeface designed for low-vision readers, and money, hashes and identifiers in its monospaced companion with tabular figures. Body copy is never smaller than 16 pixels.
  • Three themes: Paper (light), Carbon (dark) and Contrast (black on white, with text at 7:1 and interface boundaries at 4.5:1). By default the product follows your device's light, dark and increased-contrast settings. You can also choose a theme from the header of every page.
  • Every colour pair in every theme is measured by the build, which fails if text falls below 4.5:1 or interface boundaries below 3:1.
  • Status is never conveyed by colour alone. Each status stamp carries a word and a distinct glyph, confidence meters are hatched below the threshold, and verdict marks use distinct symbols.
  • Pages reflow to a 320-pixel-wide viewport without horizontal scrolling, except inside data grids, which scroll on their own.
  • Windows High Contrast and other forced-colour modes keep every boundary and the system focus colour.

Operating

  • Everything can be done with a keyboard. Every interactive element shows a two-pixel focus ring with a halo that meets 3:1 in every theme.
  • A skip link and landmarks are on every page. In the application, focus moves to the new page's heading on navigation and the title is announced.
  • Targets are 44 pixels by default and never smaller than 24.
  • The header stops being sticky on short or narrow screens so it cannot cover what has focus.
  • The only motion is a brief stamp "press" when a status changes and the slide of a dialog. Both are off when your device asks for reduced motion.

Understanding

  • Copy is plain and specific, and reuses the product's own words: "Payee hasn't signed these criteria yet" rather than an error code.
  • Forms have visible labels, descriptions and errors linked to each field, and an error summary that takes focus and links to each problem.
  • Actions you are not allowed to take stay visible, with a note saying which role is needed and which you have.
  • Actions that move money or cannot be undone open a confirmation that states exactly what will happen.
  • Toasts are announced through one shared live region, stay for at least eight seconds, pause on hover or focus, and are never the only place an outcome appears.
  • Data grids are named by a visible caption and described by a one-line summary. Charts have a text summary and a "show as table" switch.

Technical specifications

Accessibility of this website and the application relies on the following technologies to work with the combination of web browser and any assistive technologies or plugins installed on your computer: HTML, CSS, JavaScript and WAI-ARIA. The application's interactive components are built on React Aria, which provides their keyboard behaviour, focus management and ARIA semantics. These technologies are relied upon for conformance with the accessibility standards used.

Known limitations

Despite our best efforts, some parts of the application may not yet be fully accessible. We list what we know here and will update this statement as it changes.

  • Screen-reader passes of the tranche page and the review dialog with VoiceOver and NVDA are still being done by hand. Automated checks pass, but we have not yet confirmed the reading order and announcements in every state. If something reads wrongly, please tell us.
  • Zoom to 400% has not yet been verified on every route. Pages are built to reflow, and we expect it to work, but we have not finished checking.
  • Data grids are built on AG Grid. They are keyboard-operable and described by a caption and summary, and pressing Enter on a title follows the link, but very large grids can be slow to navigate cell by cell. Every grid's data is also available through the API and in the compliance packet.
  • Compliance packets are exported as PDF and as JSON. If the PDF does not work with your assistive technology, the JSON export contains the same record.
  • PayPal's pages, where a payer approves a hold or pays an invoice and where a payee connects an account, are PayPal's own and are covered by PayPal's accessibility statement.

Compatibility

The website and the application are designed to work with current versions of Chrome, Firefox, Safari and Edge on desktop and mobile, with the screen readers built into those platforms and with NVDA and JAWS on Windows. They are not designed for Internet Explorer.

Feedback and contact

We welcome your feedback on the accessibility of Milestone Ledger. If you encounter a barrier, or need information in another format, please tell us:

  • Email accessibility@milestone-ledger.com.
  • Or open an issue on the repository, if you are comfortable with it being public.

We aim to respond within 5 business days. Please include the page or step you were on, the browser and assistive technology you were using, and what happened.
